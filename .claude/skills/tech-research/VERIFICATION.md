# 検証手順

調査レポートの数値を、書いた本人とは独立に裏取りする。

## 前提

あなたは検証専任のエージェントである。**レポート本文だけを受け取り、参考URL一覧と脚注定義は受け取らない。**

これは意図的な設計である。調査時に集めたソースを見ながら検証すると、確証バイアスによって「そのソースに書いてあるから正しい」と判断してしまう。数値ごとにゼロから出典を探すことで、はじめて独立した検証になる。

渡された本文に脚注参照（`[^1-3]` など）が残っていても、その定義は手元にない。無視してよい。

## 手順

### 1. 数値の抽出

本文からすべての数値を抽出し、一覧にする。対象は次のとおり。

- 割合、倍率、増減率（`54%`、`3倍`、`−7.2%`）
- 金額、市場規模（`366億ドル`、`CAGR 65.5%`）
- 件数、規模（`1,300以上のエージェント`、`月35,000件`）
- 日付、時期（`2025年12月 Preview`、`2024年4月に発足`）
- バージョン番号、仕様のステータス（`Experimental`、`v2`）

`数値未確認` と既に記載されている項目は、検証対象から除外する。

### 2. 出典の独立探索

各数値について、ゼロから出典を探す。

- WebSearch で数値そのものと文脈のキーワードを組み合わせて検索する
- 候補ページの本文は `ax` で取得する
- ライブラリや API の仕様に関する数値は Context7 で確認する（クエリ末尾に `use context7`）

`SOURCE-TIERS.md` の階層定義に従い、Tier 1 / 1.5 / 2 のソースのみを採用する。Tier 3 は採用しない。

### 3. 一次ソースへの遡及

ブログや記事が数値を引用している場合、その引用元をたどる。

- 「Gartner によると 366億ドル」と書くブログを見つけたら、Gartner の原典を探す
- 原典に到達できたらそれを出典とする
- 原典に到達できないときは「一次ソース到達不可」として扱う

孫引きを出典として採用しない。数値は転記のたびに丸められ、文脈が失われる。

**深度による差**:

- `standard`: 数値のみ遡及する。記述内容（機能の説明、アーキテクチャの解説）はソースの取得確認まででよい
- `deep`: 数値に加えて、製品仕様や機能に関する記述も一次ソースまで遡及する

### 4. 判定

各数値を次の3つに分類する。

| 判定 | 条件 |
|---|---|
| 一致 | Tier 1-2 のソースで同じ数値を確認できた |
| 不一致 | Tier 1-2 のソースに数値はあるが、本文と異なる |
| 発見不能 | Tier 1-2 のソースで数値を確認できなかった |

数値の丸めによる差（`65.5%` と `約66%`、`366億ドル` と `36.6 billion USD`）は一致として扱う。桁や単位が違う場合は不一致とする。

## 出力

次の形式で報告する。本文の書き換えは行わない。親エージェントが反映する。

~~~markdown
## 検証結果

検証対象: 数値 42件
一致: 38件 / 不一致: 2件 / 発見不能: 2件

### 一致

すべての一致項目について、確認したソースを列挙する。

- 1.1「AIOps市場規模 366億ドル」
  Gartner "Market Guide for AIOps Platforms" 2025-08-14 〔第三者調査〕 https://example.com/...
- 1.2「AI監視機能の採用率 54%」
  CNCF Annual Survey 2025, 2026-01-30 〔第三者調査〕 https://example.com/...

### 不一致

- 2.1「インシデント解決時間の短縮率」
  本文の値: 50%
  確認した値: 48%
  ソース: PagerDuty 2025年決算資料 2026-02-11 〔一次統計〕 https://example.com/...
  備考: 本文の値はベンダーブログの概数表記と一致する。決算資料の値が一次ソース。

### 発見不能

- 1.4「MTTR 改善幅 3倍高速化」
  探索した範囲: Datadog / PagerDuty / Rootly の公式ブログ、Gartner および IDC のレポート、DORA レポート 2024-2025
  結果: 複数のベンダーブログが同一の数値を記載するが、いずれも出典を示さない。一次ソースを特定できず。
~~~

一致項目についてもソースを列挙する。親はこれを使って参考URL一覧を補強できる。

## 報告に含めないもの

- 文章表現に関する指摘
- 構成や見出しに関する提案
- 数値以外の事実確認（`standard` の場合）

検証の役割は数値の裏取りに限定する。範囲を広げると、本来の目的である数値の精度が落ちる。
