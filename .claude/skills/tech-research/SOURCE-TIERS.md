# ソース信頼階層

調査で参照してよいソースの範囲と、数値を引用してよい条件を定める。

## 階層

### Tier 1 — 一次ソース

- 公式ドキュメント（製品ドキュメント、API リファレンス、リリースノート）
- ベンダーの公式発表（プレスリリース、製品ページ、GA アナウンス）
- 標準化団体の仕様書（OpenTelemetry、CNCF、IETF、W3C、OASIS など）
- 企業の IR 資料（決算資料、投資家向け説明会資料、有価証券報告書）
- 政府・公的機関の統計（総務省、経産省、NIST、ENISA など）
- ソースコードリポジトリ（README、CHANGELOG、公式サンプル）

数値の引用可。無印で記載する。

### Tier 1.5 — ベンダー自社計測

- ベンダー公式ブログに掲載された、自社製品の性能・効果に関する数値
  - 例: `datadoghq.com/blog`、`techcommunity.microsoft.com`、`aws.amazon.com/blogs`、`komodor.com/blog`、`rootly.com/blog`
- ベンダーが公開する自社顧客の事例（導入効果、削減率）

数値の引用可。ただし**本文に `（ベンダー自社計測）` と明記する**。

自社計測は方法論が非開示で、条件のよい事例を選んで出している可能性が高い。排除すると製品比較が書けず、無条件に採用すると宣伝文の転載になる。ラベルで読者に判断材料を渡す。

同じベンダーのブログでも、製品仕様の説明（アーキテクチャ、設定方法、対応プロトコル）は Tier 1 として扱う。ラベルが必要なのは効果・性能の数値だけ。

### Tier 2 — 第三者調査

- 調査機関のレポート（Gartner、IDC、Forrester、Stanford HAI、DORA、Uptime Institute など）
- 査読付き論文（arXiv のプレプリントは査読なしのため Tier 2 に含めない。参照する場合は「プレプリント」と明記し Tier 1.5 相当に扱う）
- 業界団体の年次調査（CNCF Annual Survey、Stack Overflow Developer Survey など）
- 著名カンファレンスの登壇資料（KubeCon、re:Invent、Google Cloud Next の公式セッション資料）

数値の引用可。無印で記載する。

### Tier 3 — 引用禁止

- 個人ブログ、Medium、Qiita、Zenn、note の記事
- SEO 目的のまとめ記事、比較サイト、アフィリエイトサイト
- AI 生成と推測される記事（出典なしの断定、不自然に網羅的な構成、実在しない引用）
- 出典を示さないニュース記事
- 他のレポートやブログからの孫引き（引用元をたどって Tier 1-2 に到達できる場合はそちらを参照する）

記述の裏付けにも使わない。発見の手がかりとして読むことは構わないが、レポートには載せない。

## 判定に迷うケース

| ケース | 判定 |
|---|---|
| ベンダー公式ブログの製品仕様説明 | Tier 1 |
| ベンダー公式ブログの効果測定値 | Tier 1.5 |
| ベンダー公式ブログが引用する Gartner の数値 | Gartner 原典を探して Tier 2。見つからなければ引用しない |
| GitHub の公式リポジトリの README | Tier 1 |
| GitHub の個人リポジトリの README | Tier 3 |
| ニュースサイト（InfoQ、The Register、Publickey）の記事 | 一次ソースへのリンクがあればそれを参照して Tier 1。なければ Tier 3 |
| 企業の採用ページや事例ページ | Tier 1.5 |
| arXiv プレプリント | Tier 1.5 扱い。「プレプリント」と明記 |
| Wikipedia | 引用しない。出典欄から一次ソースをたどる |

## 情報の鮮度

- 原則として直近12か月に公開された情報を使う
- それ以前の情報は「歴史的経緯」として位置づけを明示する（例: `Dynatrace Davis AI は 2017年から因果分析を提供`）
- 参考URL一覧には各ソースの公開日を併記する
- 公開日が不明なソースは `公開日不明` と記載する。公開日不明のソースから数値を引用しない

技術動向は12か月で内容が変わる。プレビュー段階と GA 後で仕様が別物になる製品は珍しくない。

## 数値が Tier 1-2 で見つからないとき

項目を削除しない。定性的な記述だけを残して数値を落とすこともしない。

`数値未確認` と明記して項目を残す。

```markdown
- MTTR 改善幅: 数値未確認（複数のベンダーが「3倍高速化」と記載するが、一次ソースを特定できず）
```

「探したが一次ソースが存在しない」ことは、読者にとって情報価値がある。業界で数値が独り歩きしている兆候でもある。

## 深度別の適用範囲

| 深度 | 使用可能な階層 |
|---|---|
| quick | Tier 1 のみ |
| standard | Tier 1 / 1.5 / 2 |
| deep | Tier 1 / 1.5 / 2 |
