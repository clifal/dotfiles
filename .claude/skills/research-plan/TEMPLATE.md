# リサーチ依頼書テンプレート

Research 系 skill（`mattpocock-skills:research` など）の背景エージェントに渡す依頼書の雛形。

## 置き場所の規約

```
research/
  TEMPLATE.md                  このファイル
  <topic>/
    plan.md                   依頼書（このテンプレを埋めたもの）
    findings.md                調査結果（エージェントが書く）
    findings-2.md              追加調査の結果（差分調査ごとに連番）
```

`<topic>` は英小文字ケバブケース。1 トピック 1 ディレクトリ。同じトピックの追加調査は同じディレクトリに積む。

## 渡し方

会話で次のように起動する。背景エージェントは会話の文脈を引き継がないため、依頼書 1 枚で自己完結させる。

```
research/<topic>/plan.md に従って調査して
```

## 調査深度の定義

依頼書の「調査深度」欄で 1 つ選ぶ。

- **quick** — 各主張に出典 URL を付ける。格付けも検証もしない。前提を素早く掴みたいとき。
- **standard** — quick に加えて、各出典を Tier 1 / Tier 2 に格付けし、一次ソース比率を明記する。各主張に「確認済み」「推測」のラベルを付ける。既定値。
- **deep** — standard に加えて、別のエージェントに本文だけ（出典一覧を渡さずに）検証させ、出典を独立に取り直させる。一致数・修正数・裏が取れなかった項目を付録に残す。設計判断や外部公開の根拠にするとき。

## 7. 情報源の格付け

<!-- 「一次情報のみ」だけでは抽象的すぎて、エージェントが自分で解釈する。具体的に列挙する。 -->

### Tier 1: 一次情報（優先）

- 公式ドキュメント
- ソースコード本体（リポジトリのファイルパスと行を示すこと）
- 仕様書・RFC
- 一次 API リファレンス、公式の料金ページ

### Tier 2: 条件付き（一次情報が存在しない場合のみ。二次であると本文に明示する）

- ベンダー公式ブログ
- GitHub の issue / discussion / PR
- CNCF 等の中立団体によるレポート・調査

### Tier 3: 使用禁止

- まとめ記事、比較サイト
- Qiita / Zenn / Medium などの個人解説
- 日付が不明な記事
- 出典を示さない AI 生成らしき記事

## 8. 出力要件

<!-- 形を決めないと、後から裏を取れない文章が出てくる。記事や設計書の根拠に使えなくなる。 -->

`research/<topic>/findings.md` に 1 ファイルで書く。構成は次の順。

1. **要約** — 結論を先に。数百字。
2. **本文** — 問い（RQ）ごとに節を立てる。
3. **出典** — 脚注形式。各出典に「タイトル / 公開日または更新日 / Tier / URL / アクセス日」。公開日が不明なら「公開日不明」と書く。
4. **未解決** — 10 章のプロトコルに従う。

記述のルール:

- 事実には必ず出典を付ける。出典のない主張を書かない。
- 確認できた事実と、そこからの推測を書き分ける。推測には「推測」と明記する。
- 料金・機能・提供状況は変わるため、アクセス日を必ず残す。
- 言語は日本語。技術用語・製品名・API 名・設定キーは原語のまま。

## 9. 完了条件

<!-- 無いと、どこまで調べれば終わりか分からず、浅いまま出てくるか、延々と広がる。 -->

- 5 章の全 RQ に、答えまたは「未解決」の記載がある
- 選んだ調査深度の要件を満たしている
- Tier 2 を使った箇所に、二次情報である旨の明示がある

## 10. 不明時のプロトコル

一次情報で埋まらない項目は、必ず次の 3 点を書く。空欄で飛ばさない。

1. **何が不明か**
2. **なぜ埋まらなかったか** — 分類する
   - ドキュメントに記載がない
   - 有償プランの機能で公開情報がない
   - ソースコードの読解が必要
   - 動的描画などで静的取得できなかった
   - 情報が新しすぎる / 古すぎる
3. **次に何を見れば埋まるか** — 読むべきソースファイル、issue 番号、問い合わせ先

<!-- 単に「不明」とだけ書くと、次回また同じ場所を掘り直す。どこまで掘ったかが残れば差分で追える。 -->

## 11. エージェントへの実行指示

<!-- 背景エージェントは会話の文脈を持たない。この節だけで作業が完結するようにする。 -->

- この依頼書を最初に通読し、5 章の問いを作業単位にする
- 7 章の格付けに従って情報源を選ぶ。Tier 3 は使わない
- 8 章の構成で `research/<topic>/findings.md` に書き出す
- 9 章の完了条件を自分で照合してから終了する
- 依頼書の記述と実際の状況が食い違う場合は、勝手に解釈を変えず、findings.md の「未解決」に記録する
