# 調査依頼: {{NAME}}

{{NAME}} について、一次情報源だけを使って調べ、結果を `{{OUT_DIR}}/research-notes.md` に日本語で書き出してください。ディレクトリが無ければ作成します。今日は {{DATE}} です。

一次情報源とは、公式ドキュメント、公式サイト、GitHub などのリポジトリと LICENSE ファイル、各クラウドベンダーの公式製品ページとドキュメント、CNCF Landscape の公式データ（`cncf/landscape` リポジトリの `landscape.yml`）です。開発元の公式ブログは公式発表として扱ってかまいません。二次的な解説記事やブログで代替しないでください。

各主張の行末に出典 URL を付けます。確認できなかった点は「未確認」と明記し、推測で埋めないでください。WebFetch / WebSearch が deferred tool なら、ToolSearch で読み込んでから使います。

## 調べる項目

### 1. 概要

- 公式の説明文（原文を引用）と、開発元・初回リリース年。
- 最新の安定版のバージョンと公開日。リポジトリの releases で確認する。
- 主要機能と、それぞれが何をするか。
- エコシステム内での位置づけ。関連製品と組み合わせた定番構成があればその名前と役割。

### 2. リポジトリとライセンス

- リポジトリの URL、主要言語、スター数（取得日を添える）。
- ライセンスは LICENSE ファイルを直接読んで確認する。一部ディレクトリだけ別ライセンスの場合はそれも書く。
- 過去にライセンス変更があれば、時期・変更前後・公式発表の URL。
- そのライセンスが利用者に何を意味するか。公式 FAQ があればそれに従う。
- 商用版・Enterprise 版があれば、OSS 版との違い。
- ソースが公開されていないソフトウェアなら、その旨と利用規約・料金体系の概要を書く。

### 3. セルフホスト以外の提供

- 開発元自身が運営する SaaS（無料枠があればその上限）。
- AWS、Google Cloud、Azure それぞれにマネージドサービスがあるか。無い場合は「無い」と書き、代わりに公式に用意されている連携方法（マーケットプレイス経由の購入、データ連携など）を書く。
- そのほかのクラウド（Oracle、Alibaba Cloud、IBM など）で見つかったもの。
- 各サービスの対応バージョンや、プラグイン制限などの公式に書かれた制約。

### 4. はじめて使うときの手順

- 公式の Getting started / Quickstart に載っている、最小構成での起動方法（Docker、パッケージ、SaaS 登録など）。コマンドは公式ドキュメントからそのまま写す。
- 初期ログイン情報やポート番号など、最初につまずきやすい点。
- 起動後に最初にやる操作を、公式ドキュメントに沿って 3〜4 段階で。画面のメニュー名は現行バージョンの表記で書く。
- 手元にデータや接続先がなくても試せる方法（サンプルデータ、デモ環境など）があれば。

### 5. CNCF Landscape

- `landscape.yml` で {{NAME}} が載っているカテゴリとサブカテゴリ。調べたコミットのハッシュも書く。
- {{NAME}} が CNCF ホストプロジェクトか、成熟度（Sandbox / Incubating / Graduated）。
- 同じサブカテゴリにあり、{{NAME}} と同じ役割を持つ OSS を 4〜6 個。サブカテゴリに役割の違うものが混ざっている場合は、役割が同じものだけを選ぶ。それぞれについて、ライセンス（LICENSE で確認）、主な用途、得意な対象、CNCF プロジェクトかどうか。
- 候補にしたが landscape に載っていなかったもの、別の項目名で載っていたものは、除外理由とともに書く。
- {{NAME}} 自体が landscape に載っていない場合は、その旨と、役割がいちばん近いサブカテゴリ名を書き、そこから同じ役割の OSS を選ぶ。

## 出力形式

項目ごとに見出しを立て、事実を箇条書きにし、各行末に出典 URL を付けます。最後に「未確認事項」と「出典一覧」を置きます。完了したら、ファイルパスと要点、未確認事項を短く報告してください。
