# 調査依頼: {{NAMES}} の比較

{{NAMES}} を比較するための事実を、一次情報源だけを使って調べ、結果を `{{OUT_DIR}}/research-notes.md` に日本語で書き出してください。ディレクトリが無ければ作成します。今日は {{DATE}} です。

対象名に版の指定（例: Kubecost v3.x）がある場合は、その系列の公式ドキュメントとリリースノートを優先し、それより前の系列の情報しか見つからない事柄はその旨を明記してください。指定された系列と一つ前の系列の間で、比較に関わる変更（構成、ライセンス、ほかの対象との関係など）があれば書きます。

一次情報源とは、公式ドキュメント、公式サイト、GitHub などのリポジトリと LICENSE ファイル、各クラウドベンダーの公式製品ページとドキュメント、CNCF Landscape の公式データ（`cncf/landscape` リポジトリの `landscape.yml`）です。開発元の公式ブログは公式発表として扱ってかまいません。二次的な解説記事、ブログ、ベンチマーク記事で代替しないでください。

各主張の行末に出典 URL を付けます。確認できなかった点は「未確認」と明記し、推測で埋めないでください。WebFetch / WebSearch が deferred tool なら、ToolSearch で読み込んでから使います。

すべての対象を同じ項目、同じ粒度で調べます。ある対象で調べた観点は、ほかの全対象でも調べ、結果を「未確認」も含めて書きます。スター数など時点で変わる値は、全対象を同じ日に取得します。

## 調べる項目

### 1. 概要

対象ごとに次を調べる。

- 公式の説明文（原文を引用）と、開発元・初回リリース年。
- 最新の安定版のバージョンと公開日。リポジトリの releases で確認する。
- 対象どうしで共通する役割と、一方にしかない役割。

### 2. 設計と動作

対象ごとに次を調べる。比較の軸になるので、公式のアーキテクチャ説明を優先する。

- 主要な構成要素と、それぞれの役割。
- データの持ち方（自前で保存するか、外部のストレージやデータベースに任せるか）。
- 動作に必要な外部の依存ソフトウェア。
- 冗長化と水平スケールの方法。公式に書かれた構成だけを書く。
- 公式に書かれたシステム要件（CPU、メモリ、ディスクなど）。

### 3. 機能の対応状況

全対象の公式ドキュメントにある機能一覧を見比べ、この役割で比較に効く機能を 8〜12 個選ぶ。選んだ機能のそれぞれについて、各対象が「対応」「プラグインで対応」「有償版のみ」「非対応」「未確認」のどれかを、出典付きで書く。「非対応」は、公式ドキュメントに非対応と書かれているか、機能一覧に載っていないことを確認した場合に限る。

機能の選び方（なぜその 8〜12 個にしたか）も 1〜2 文で書く。

### 4. リポジトリとライセンス

対象ごとに次を調べる。

- リポジトリの URL、主要言語、スター数（取得日を添える）。
- 直近 12 か月のリリース数と、最後のリリース日。
- ライセンスは LICENSE ファイルを直接読んで確認する。一部ディレクトリだけ別ライセンスの場合はそれも書く。
- 過去にライセンス変更があれば、時期・変更前後・公式発表の URL。
- 商用版・Enterprise 版があれば、OSS 版との違い。
- ソースが公開されていないソフトウェアなら、その旨と利用規約・料金体系の概要を書く。

### 5. セルフホスト以外の提供

対象ごとに次を調べる。

- 開発元自身が運営する SaaS（無料枠があればその上限）。
- AWS、Google Cloud、Azure それぞれにマネージドサービスがあるか。無い場合は「無い」と書き、代わりに公式に用意されている連携方法（マーケットプレイス経由の購入など）を書く。
- 各サービスの対応バージョンや、公式に書かれた制約。

### 6. はじめて使うときの手順

対象ごとに次を調べる。

- 公式の Getting started / Quickstart に載っている、最小構成での起動方法。コマンドは公式ドキュメントからそのまま写す。
- 起動に必要な前提（Docker、別のソフトウェアが動いていることなど）と、初期ログイン情報やポート番号。

### 7. CNCF Landscape

- 各対象が `landscape.yml` で載っているカテゴリとサブカテゴリ。調べたコミットのハッシュも書く。
- 各対象が CNCF ホストプロジェクトか、成熟度（Sandbox / Incubating / Graduated）。
- 対象どうしが同じサブカテゴリに載っていない場合は、それぞれの掲載先を書く。landscape に載っていない対象はその旨を書く。

### 8. 公式の比較・移行情報

- 各対象の公式サイトやドキュメントにある、ほかの対象との比較ページ。内容を要約し、「開発元の主張」と明記する。
- 対象どうしの間の公式な移行ガイドや互換機能（API 互換、データの取り込みなど）。

## 出力形式

番号付きの項目ごとに見出しを立て、その下に対象ごとの小見出しを、依頼文に書かれた順で置きます。ただし「3. 機能の対応状況」は、行が機能、列が対象の表にし、各セルの出典は表の下に脚注として並べます。事実は箇条書きにし、各行末に出典 URL を付けます。

最後に「未確認事項」と「出典一覧」を置きます。完了したら、ファイルパスと要点、未確認事項を短く報告してください。
