# 要件定義書テンプレート

`spec-doc` skill が `<ディレクトリ>/spec/requirements.md` を書くときの雛形。

読み手は、この件に初めて触れる人間のレビュアー。承認するか差し戻すかを、この 1 枚で判断できる状態にする。

## 書き方の決まり

- 文体は「です・ます」を使わず、常体で書く。短く言い切る
- 要件には ID を振る。機能要件は `FR-n`、非機能要件は `NFR-n`。基本設計書と段階的実装計画がこの ID で参照する
- 調査で確かめた事実には、`findings.md` の節番号を添える（例: 「findings 2.3」）
- 日本語と英数字の間に半角空白を入れる
- 箇条書きはラベルの行の下に値をネストする。「ラベル: 値。補足」と 1 行に詰めない
- 決まっていないことは「未定」と書いて 8 章に送る。空欄で飛ばさない
