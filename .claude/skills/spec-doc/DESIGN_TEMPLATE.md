# 基本設計書テンプレート

`spec-doc` skill が `<ディレクトリ>/spec/design.md` を書くときの雛形。

読み手は人間のレビュアー。要件定義書が決めた「何を作るか」に対して、「どう作るか」が妥当かを判断するために読む。

## 書き方の決まり

- 文体は常体。短く言い切る
- 要件定義書の ID（`FR-n` / `NFR-n`）で要件を参照する。要件の文言を書き写さない
- ファイルパス、クラス名、コードは書かない。実装が始まると先に古くなる。インタフェースの形、データの構造、処理の順序で書く
- 事実、数値、バージョン、制約は `findings.md` にあるものだけを使う。節番号を添える
- 日本語と英数字の間に半角空白を入れる
- 図は `<ディレクトリ>/spec/diagrams/` に置く。`archify` skill で作るか、Mermaid で書く

## 分割するとき

主要な構成要素が 5 つを超えるか、`design.md` が 600 行を超える見込みなら、`<ディレクトリ>/spec/design/` に分ける。

```text
spec/
  design/
    00-overview.md      1 章（全体構成）と 8 章（要件との対応表）
    01-<領域>.md        その領域の 2〜7 章
    02-<領域>.md
```

分け方の決まり:

- 領域は構成要素の境界で切る。章の番号で切らない。1 つの領域を読むだけで、その部分の設計が分かる状態にする
- `00-overview.md` に全体構成と対応表を集める。対応表が散ると、要件の取りこぼしを見つけられない
- 各領域ファイルの冒頭に、扱う構成要素と、隣の領域との境界を 1 段落で書く
- 領域をまたぐ処理は `00-overview.md` の 1 章に置き、各領域ファイルからは参照する
