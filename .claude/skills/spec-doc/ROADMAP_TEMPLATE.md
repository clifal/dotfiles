# 段階的実装計画テンプレート

`spec-doc` skill が `<ディレクトリ>/spec/roadmap.md` を書くときの雛形。

この文書はゴールを定義しない。ゴールは要件定義書と基本設計書にあり、ここには到達の順序だけを書く。順序は人員や期限で組み替わるが、ゴールは組み替わらないため、別のファイルに分ける。

## 書き方の決まり

- 文体は常体
- 要件は ID（`FR-n` / `NFR-n`）で参照する。要件の内容を書き写さない
- 設計は節番号で参照する（例: 「design 4.1」）
- ファイルパスとコードは書かない。スライスに着手する時点で古くなっている
- 日本語と英数字の間に半角空白を入れる

## スライスの切り方

スライスの規約は `mattpocock-skills:to-tickets` に合わせる。この文書をそのままチケット化へ渡すためである。

- 1 スライスは全レイヤー（スキーマ、API、画面、テスト）を貫く縦の 1 本にする。1 レイヤーだけの横割りにしない
- 完了したスライスは、それ単体でデモか検証ができる
- 1 スライスは 1 つの context window に収まる大きさにする
- 各スライスに、先行するスライス（blocking edges）を書く。先行の無いスライスはすぐ着手できる
- 下ごしらえ（prefactoring）があるなら最初に置く

広い改修は縦に割らない。シンボルの改名や共有型の変更のように、1 回の変更で呼び出し側が一斉に壊れるものは、どう縦に切っても CI が緑にならない。expand → migrate → contract の順に並べる。

- expand: 新しい形を古い形の隣に足す。何も壊れない
- migrate: 呼び出し側を、影響範囲の単位（パッケージごと、ディレクトリごと）で移す。古い形が残っているので、各段階で緑を保てる
- contract: 呼び出し側がいなくなった古い形を消す。全 migrate を先行に持つ
