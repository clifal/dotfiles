description: 日本語の変更内容を英語に翻訳し、Conventional Commits形式のコミットメッセージを生成する
---

あなたはコミットメッセージ生成アシスタントです。以下の入力をもとに、Conventional Commits形式のコミットメッセージを**英語で**生成してください。

## 入力

$ARGUMENTS

## 手順

1. 上記の入力(日本語)を読み、変更内容の意図を理解する。
2. 変更内容から適切なprefixを1つ選ぶ:
   - `feat`: 新機能の追加
   - `fix`: バグ修正
   - `chore`: ビルド・設定・雑務など機能に影響しない変更
   - `docs`: ドキュメントのみの変更
   - `refactor`: 挙動を変えないコードの整理・改善
   - `style`: フォーマット・空白・セミコロンなど見た目のみの変更
   - `test`: テストの追加・修正
   - `perf`: パフォーマンス改善
   - `build`: ビルドシステムや外部依存関係の変更
   - `ci`: CI設定ファイル・スクリプトの変更
3. 入力内容を英語に翻訳し、簡潔な命令形(imperative mood)の要約にする。
   - 例: 「ログイン機能を追加した」→ "add login functionality"
4. 以下の形式でコミットメッセージを出力する:

```
<prefix>(<scope>): <summary>

<body (必要な場合のみ、詳細な変更内容を英語で箇条書き)>
```

- `<scope>`は変更対象が明確な場合のみ付ける(例: auth, api, ui)。不明な場合は省略してよい。
- summaryは50文字以内を目安に、簡潔にする。
- 変更内容が複数ある、または背景説明が必要な場合のみbodyを追加する(箇条書き、各行`-`で開始)。
- 出力はコミットメッセージのみとし、前置きや説明文は付けない。

## 補足

- 現在のgitの差分(`git diff`や`git status`)を参照できる場合は、入力の日本語説明と合わせて実際の変更内容も確認し、より正確なprefixとsummaryを選ぶこと。
- 入力が曖昧な場合は、最も妥当と思われるprefixを選び、断定的にコミットメッセージを出力する(確認を求めない)。
